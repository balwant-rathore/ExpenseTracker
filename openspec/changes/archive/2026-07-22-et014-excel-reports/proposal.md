## Why

Finance can currently pull monthly reimbursement data only as JSON from
`GET /api/reports/monthly-reimbursement` (built in ET012). `docs/FRS.md` §10.1.2 requires the
report to be "exportable to Excel," and `docs/SDS.md` §1.4/§5.6/§8.4 specify the deliverable is
a Microsoft Excel (`.xlsx`) file generated by the backend via ClosedXML. ET014 closes that gap by
generating the actual `.xlsx` workbook, per the ET012/ET014 boundary already recorded in
`openspec/specs/monthly-reimbursement-report/spec.md` ("ET014 ... replaces this response with
the `.xlsx` format ... reusing this same endpoint and underlying query").

## What Changes

- **BREAKING**: `GET /api/reports/monthly-reimbursement` now returns the report as an `.xlsx`
  binary (`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`,
  `Content-Disposition: attachment; filename="Monthly-Reimbursement-{yyyy}-{MM}.xlsx"`) instead
  of the JSON body it returned under ET012. The JSON response DTO
  (`MonthlyReimbursementReportResponse`) and its `200 OK` JSON contract are removed.
  (`docs/FRS.md` §10.1.2; `docs/SDS.md` §5.6, §8.4)
- Same `year`/`month` query parameters, same `Finance`-only authorization, and the same
  `400 VALIDATION_ERROR` behavior for missing/out-of-range values are preserved unchanged —
  only the success response's representation changes. (`docs/SDS.md` §5.6)
- The existing data query (`ReportService.GetMonthlyReimbursementAsync`, filtering to
  `Reimbursed` expenses within the requested month, `docs/FRS.md` §10.1.1) is reused as-is; a
  new `Infrastructure`-layer component converts that same record set into an `.xlsx` workbook,
  keeping the ClosedXML dependency out of `Application` (per `AGENTS.md` §5 layering:
  `Application` -> `Domain` -> `Infrastructure`, external libraries live in `Infrastructure`).
- A month with zero reimbursed expenses still returns `200 OK` with a valid workbook containing
  only the header row (no data rows) — matching the "empty result, not `404`" behavior the
  current JSON endpoint already has (`openspec/specs/monthly-reimbursement-report/spec.md`,
  "A month with no reimbursements returns an empty result").
- Workbook columns exactly match `docs/FRS.md` §10.1.1: Employee, Expense Number, Category,
  Amount, Currency, Approval Date, Reimbursement Date. Date cells use a real Excel date format
  (`yyyy-MM-dd`), consistent with company-local-timezone storage (BR-10, `docs/SDS.md` §1.5).

## Capabilities

### New Capabilities
(none — no new capability area; this extends the existing reporting capability)

### Modified Capabilities
- `monthly-reimbursement-report`: the success response of
  `GET /api/reports/monthly-reimbursement` changes from a JSON body to an `.xlsx` file download,
  per the boundary already documented in that capability's spec. Validation (`400`), Finance-only
  authorization (`403`/`401`), and report data scope (Reimbursed-only, month-filtered, Approval
  Date reflecting Compliance Approval for Client Entertainment) are unchanged and stay as
  currently specified.

## Impact

- **Api**: `ReportsController.MonthlyReimbursement` action changes its return type from
  `Ok(MonthlyReimbursementReportResponse)` to a file result (`.xlsx` bytes with the appropriate
  content type and `Content-Disposition` header).
- **Application**: `IReportService`/`ReportService` gain a method (or the existing method is
  wrapped) that produces the workbook bytes for a given year/month, delegating actual
  spreadsheet construction to a new `Infrastructure` abstraction rather than building it inline.
  `MonthlyReimbursementReportResponse` (the JSON wrapper) is removed as dead code.
- **Infrastructure**: new ClosedXML-based Excel-generation component (e.g.
  `IExcelReportGenerator` / `MonthlyReimbursementExcelGenerator`), registered in DI, with no
  business/query logic of its own — it only renders an already-fetched record set to bytes.
- **Dependencies**: adds the `ClosedXML` NuGet package to the `Infrastructure` project (already
  named in `docs/SDS.md` §2 tech stack; not previously installed).
- **Tests**: `MonthlyReimbursementReportTests.cs` (integration) and `ReportServiceTests.cs` /
  `MonthlyReimbursementQueryValidatorTests.cs` (unit) need updates to assert on the `.xlsx`
  response instead of the JSON body; validation and authorization test cases carry over
  unchanged in intent.
- **Ticket**: `docs/TICKETS.md` ET014 ("Monthly reimbursement Excel generation using
  ClosedXML"), FRS §10.
